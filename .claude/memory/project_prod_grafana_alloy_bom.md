Prod `grafana/alloy` collector (added 4fa7fb0a; ships Docker logs→Loki + cAdvisor metrics→Prometheus on Grafana Cloud) crash-looped (exit 1) right after config. Cause: `/opt/mypickuae/.env` had a UTF-8 BOM (`﻿` = bytes `EF BB BF`) glued to the front of 5 of 6 Grafana values — right *after* the opening quote (`URL="<BOM>https://...`). Alloy died at config build: `failed to parse remote url "﻿https://..." first path segment in URL cannot contain colon`. Polluted: LOKI_URL, PROMETHEUS_REMOTE_WRITE_URL, LOGS_USERNAME, METRICS_USERNAME, USERNAME; only TOKEN was clean.

**Why:** classic Windows copy-paste artifact (same hazard family as [[feedback_msys_grep_cr_pipe]] / [[feedback_local_lint_diagnostic_level]] CRLF issues).

**How to apply:** strip with `LC_ALL=C sed -i 's/\xEF\xBB\xBF//g' .env`, then `docker-compose up -d --force-recreate alloy` (plain `restart` won't re-read .env; env injected at container CREATE). Verify: container stays `Up`, logs show `Done replaying WAL` with no 4xx/5xx and `loki.*`/`prometheus.remote_write` nodes evaluate clean. Benign noise to ignore: `remotecfg ... noop client`, containerd/crio factory failures, `/dev/kmsg` OOM-detection. Prod box uses standalone `docker-compose` v5.1.4 (NO `docker compose` plugin). Compose file is `/opt/mypickuae/docker-compose.yml`. **BOM root FIXED 2026-06-13:** reset 5 `PROD_GRAFANA_CLOUD_*` GitHub secrets (LOKI_URL/PROMETHEUS_REMOTE_WRITE_URL/USERNAME/METRICS_USERNAME/LOGS_USERNAME — TOKEN was clean) + the matching SSM params `/mypickuae/production/grafana/*`. Prod = AWS EC2 i-0f982d225cd7f140a via SSM ([[reference_prod_rds_ssm_debug]]).

**Part 2 — cAdvisor "No data" in Grafana (FIXED 2026-06-13):** after BOM fix, metrics shipped (samples_total>0, failed=0) but per-container memory dashboards showed No data. Cause: Alloy's `prometheus.exporter.cadvisor` only mounted `docker.sock`, so cAdvisor saw ONLY the host root cgroup — every `container_*` metric had just `id="/"` and NO `name` label. On Amazon Linux 2023 (cgroup **v2**) cAdvisor must read host fs to enumerate per-container cgroups. Fix = add to alloy service: `privileged: true` + mounts `/:/rootfs:ro`, `/sys:/sys:ro`, `/var/lib/docker/:/var/lib/docker:ro`, `/dev/disk/:/dev/disk:ro`, `/var/run:/var/run:ro`, `/dev/kmsg:/dev/kmsg`, then recreate. Verify via the exporter's raw metrics: `curl http://<alloy-ip>:12345/api/v0/component/prometheus.exporter.cadvisor.docker/metrics` → `container_memory_working_set_bytes{name="mypickuae-..."}` now present (went 1 series→44, with `name` labels for every container). Dashboard query that works: `container_memory_working_set_bytes{name=~"mypickuae-.*"}`. Full host scan raised alloy RAM ~60→190 MiB so bumped `mem_limit` 256m→384m. Fixed at source in `deploy-prod.yml` heredoc + `backend/docker-compose.prod.yml`; live box patched directly (workflow's `if ! grep '^  alloy:'` guard means it won't re-append to the existing box). Grafana stack = `slimpiranha538`; ingestion token is write-only (can't query via API, only the UI's data source can read).
