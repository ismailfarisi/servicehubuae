UGC marketplace **Slice 3 = brief/bid marketplace** (builds on [[project_ugc_licensing_slice2_architecture]]'s 2a/2b/2c escrow+rights engine). A vendor posts a creative **brief**, creators place auction **bids** (pitch-first, creator names price), vendor **accepts** one (escrow hold), creator **delivers** an owned reel, vendor **approves** → capture + credit creator gross−20% + mint a standard `reel_license_grant` (so 2c pin/download "just works" on a brief-sourced grant). Spec/plan: `docs/superpowers/{specs,plans}/2026-06-10-ugc-licensing-brief-bid-*`.

**Part 3a (core vertical) — merged to master via PR #272 (squash 9ae77d50), 2026-06-10.** Lifecycle happy path only; 3b/3c deferred.

**Cross-cutting hardening — DONE via PR #278 (squash d949de58), 2026-06-11.** The flagged hole: ALL of `licensing-vendor.routes.ts` (offers 2a/2b/2c + briefs 3a) was gated by one `vendorMembership("analytics.read")`, so a read-only `viewer` could commit vendor funds. KEY GOTCHA discovered: the seeded `role_permissions` matrix (migration 1746500000000) gives BOTH `analytics.read` AND `payouts.read` to owner/manager/**viewer** — so tightening to `payouts.read` (the originally-suggested fix) would NOT have closed it. `bank.read` is held only by owner+manager (NOT viewer/staff). Fix: split the route file into two same-prefix Elysia instances combined via `.use().use()` — reads (GETs)→`vendorMembership("payouts.read")`, mutations (POST/PATCH/DELETE)→`vendorMembership("bank.read")`. Elysia `as:"scoped"` derives bake each route's guard chain into the route, so same-prefix merge has no method+path collision and no guard bleed (adversarially verified). Added a hardening test (viewer 200 on read, 403 INSUFFICIENT_VENDOR_PERMISSION on createBrief+acceptBid) + granted owner payouts.read+bank.read (and viewer payouts.read) in all 4 licensing suites' `__setMapForTests`. NO new permission, NO migration, read-only refactor. Vendor roles: owner/manager have bank.read (full access retained); viewer/staff blocked from mutations.
