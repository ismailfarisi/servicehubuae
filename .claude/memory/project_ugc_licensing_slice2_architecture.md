UGC marketplace Slice 2 Part 2a (**merged to master via PR #269**, 2026-06-09, on top of merged Slice 1 [[project_vendor_reel_studio]]): vendors make a price **offer** to license a creator's reel, funds are **held in escrow**, creator **accepts/declines** (or it expires after 7d), and on accept the creator is credited **gross − 20%** with a rights-grant recorded.

Key architecture (new `domain/licensing/` in reels-service):
- **3 tables** (142→145): `reel_license_offers` (status pending_creator→completed/declined/expired/cancelled), `reel_license_escrow_holds` (held→captured/released, unique `idempotency_key`, `settled_payout_id` for payout netting), `reel_license_grants` (gross/fee/net snapshot + `wallet_transaction_id`). Enum columns are **varchar, not Postgres enum types** (deliberate — avoids ALTER TYPE churn for 2b's added statuses); so the pg-enum count stayed 69.
- **`FundingRail` seam** (hold/capture/release) with two impls, vendor picks per offer: `PayoutBalanceRail` (reserves against `commissions.vendor_earning WHERE status='pending'` minus active holds; capture/release are no-ops — the hold ROW STATE is the reservation) and `StripeChargeRail` (manual-capture PaymentIntent = native escrow; behind a `ChargeGateway` seam with a `FakeChargeGateway` test double, mirroring NoopStripePayoutInitiator). Stripe client is `null as unknown as Stripe` when unconfigured — payout-balance flow works without Stripe; only stripe-funded offers touch it.
- **acceptOffer money-critical invariant:** grant insert + wallet credit + hold→captured + offer→completed all in ONE `AppDataSource.transaction`, and the irreversible rail `capture()` is the **LAST** op before commit (capture-last) so any DB failure rolls back before money moves. `lockOffer` pessimistic_write serializes accept/decline/cancel/expire.
- **Payout settlement:** captured payout_balance holds net into the vendor's next payout in `order-service/domain/commission/payout.service.ts` createPayout — subtract licenseSpend BEFORE the Stripe transfer, stamp `settled_payout_id` AFTER save (save+stamp wrapped in one tx); `return null` (no payout) when net-after-license ≤ 0 so holds stay unsettled and net against a future payout. `estimateForVendor` subtracts the same sum read-only (adds `license_spend_total`).
- **Routes (no gateway change — already proxied):** vendor `/vendor/reels/licensing/{offers POST/GET, offers/:id/cancel, balance}` (vendorMembership("analytics.read"), member.vid); creator `/me/creator/licensing/{offers/:id/accept, decline, offers GET}` (jwtAuth, user.id). Expiry: BullMQ `reels-license-expiry` cron */15.
- **Frontend:** vendor offer modal + outbox in vendor-dashboard (`/licensing`); **card funding gated "coming soon"** (no `@stripe/stripe-js` dep yet) — payout-balance path fully functional. Creator inbox in apps/web `account/creator/licensing`.
- Settings (site_settings, all defaulted): `reels_license_platform_fee_rate` 0.2, `reels_license_offer_ttl_hours` 168, `reels_license_min_offer_fils` 5000.
- Test: `apps/reels-service/tests/integration/licensing-escrow.test.ts` — 9 pass, both rails, exact money assertions; payout-balance funding seeds a `commissions` row (NOT `reel_commissions`). Spec/plan: `docs/superpowers/{specs,plans}/2026-06-09-ugc-licensing-escrow-*`.

**Part 2b (counter-offer negotiation) — merged to master via PR #270 (squash 2592bea0), 2026-06-09.** Adds the negotiation loop: creator `counterOffer` (releases vendor hold → status `countered`, amount_fils=creator's price, fresh TTL); vendor `acceptCounter` (re-hold countered amount → captureAndComplete, credits gross−20%), `reOffer` (new hold → back to pending_creator), or cancel. Key facts: (1) **hold invariant** — a `held` hold exists ONLY in `pending_creator`; `countered` has NO hold (platform never holds vendor funds while waiting on vendor). (2) DRY refactor extracted `placeHold`/`captureAndComplete`/`recordEvent` from 2a's create/accept (behaviour-preserving, capture-LAST kept); 2b actions reuse them. (3) `releaseActiveHold` returns boolean → `released` event only emitted when a hold actually moved. (4) New table `reel_license_offer_events` (append-only audit, varchar-backed `ReelLicenseEventType` 9 values, FK CASCADE) + `countered_at` column; 145→146 tables, migration `1781000000000`, NO new pg-enum types. (5) cancel + `expireDueOffers` extended to sweep `countered` too. (6) NO order-service change (2a payout netting already covers captured holds). Test: `licensing-counter.test.ts` 11 pass (counter/accept-counter/re-offer/cancel/expire/403s/event-trail-order, exact money). **The two reels integration files can't co-run in one `bun test` (shared singleton AppDataSource — first afterAll destroy() kills the other's conn); each green standalone, REELS_LIVE_DB-gated so CI never co-runs them.**

**Part 2c (rights delivery) — merged to master via PR #271 (squash 82016006), 2026-06-10.** How a vendor ACTS on a granted license; **moves no money** (grant is read-only input), no order-service change. Adds 2 tables (146→148, varchar enum `ReelFeaturePlacement` product|storefront, NO new pg-enum types), migration `1781100000000`: `reel_license_features` (PDP/storefront pins, soft-delete=unpin) + `reel_license_downloads` (append-only download-mint audit). New `RightsService` in `domain/licensing/` (separate from money LicensingService): `pinFeature`/`unpinFeature`/`requestDownload`/`listGrants`/`listFeaturesForGrant`/`listFeaturedReels`. Invariants: (1) every vendor action gated by `loadActiveGrant` (404 missing / 403 not_your_grant / `grant_not_active` if revoked_at set or expires_at past); (2) scope gating `scopeAllowsPin`=in_platform|both, `scopeAllowsDownload`=off_platform|both; (3) public `GET /reels/featured?product_id=|vendor_id=` filters LIVE grants in SQL (`g.revoked_at IS NULL AND (expires_at IS NULL OR >now()) AND scope IN(in_platform,both)`) + `r.deleted_at IS NULL` — revoked/expired/deleted drop with NO cleanup job; (4) `DownloadProvider` seam (Fake + CloudflareStreamDownloadProvider POSTing `{accountId}/stream/{assetId}/downloads`, `ServiceUnavailableError` on unreachable/not-ready) mirrors 2a ChargeGateway; container picks real-vs-fake on `config.cloudflareStream.accountId/apiToken`. **Public route = only 2 registrations** (route file + libs/guards `isPublicRoute` `if(isRead && path==="/reels/featured")`) because proxy.ts already has generic `/reels` prefix. Storefront single-live-pin (NULL product_id, `uq_rlf_surface` can't constrain it) backstopped by DB partial-unique `uq_rlf_storefront` (grant_id,placement WHERE product_id IS NULL AND deleted_at IS NULL) + idempotent `23505` re-fetch in pinFeature. Test `licensing-rights.test.ts` 12 pass (direct grant insert seeding — grant.offer_id is NOT NULL so seed a throwaway completed offer first; offers table uses `rights_scope`/`funding_source` cols, grant entity uses `scope`). **Error class is `ServiceUnavailableError` (NOT `ServiceUnavailable`) from @mypickuae/plugins.** Frontend: vendor-dashboard grants list (pin/unpin/download) + apps/web featured rail prepended on PDP (`product-reels.ts` useFeaturedReels) + vendor storefront.
